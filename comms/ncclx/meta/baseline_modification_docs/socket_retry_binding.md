# Preserve socket options across retries

`v2_30/src/os/linux.cc` and `v2_32/src/os/linux.cc` recreate a failed connect socket in `ncclOsSocketResetFd`. The replacement previously lost `SO_BINDTODEVICE` and `IP_TOS` / `IPV6_TCLASS`, so subsequent attempts could use a different interface or lose their configured traffic class. In v2.30, `ncclSocketConnect` sets the interface from `localIfName`, and `NCCL_SOCKET_TOS_CONFIG` supplies the traffic class. v2.32 has the same reset hazards even though its initial Meta interface-selection and traffic-class configuration integration is not present.

Read the binding and traffic class from the existing descriptor and apply them to the replacement before `dup2`. Select `IPPROTO_IP` / `IP_TOS` for IPv4 and `IPPROTO_IPV6` / `IPV6_TCLASS` for IPv6. An unbound socket needs no interface update, but its traffic class must still be preserved. Any option read or write failing follows the existing cleanup path, closing the replacement and retaining the original descriptor. Descriptor numbering and the existing nonblocking/TCP flag setup are unchanged.

This is a small change at the Linux descriptor-replacement boundary because these options belong to the socket being replaced; no public API or socket structure change is needed. Keep it across upstream upgrades until the reset path preserves interface bindings and traffic classes upstream.

`meta/tests/SocketRetryTest.cc` covers IPv4/IPv6 and blocking/nonblocking sockets using `lo`: repeated resets, connection refusal followed by listener recovery and payload delivery, unbound sockets, descriptor/flag preservation, option-read failures, and exhaustion after three retries. Each scenario runs with the default traffic class left unset and with a nonzero DSCP value; traffic-class assertions mask the kernel-owned ECN bits. The AF_UNIX descriptor case verifies that a traffic-class read failure after a successful interface read retains the original descriptor. The test targets link each version's actual internal library and set a test-local retry count of three with 1 ms backoff. Loopback refusal validates retry count/backoff, not elapsed time for kernel SYN timeout against a blackholed peer. The library defaults are unchanged.
